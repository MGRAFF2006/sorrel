01 / THE MODEL

A different unit of work

A task, its changes,
and a review.

Each lane keeps its own history. Hub reviews compare recorded snapshots, so discussion stays attached to the work being reviewed. Lanes currently share a working directory; concurrent agents still need separate checkouts.

01

Lanes

Separate histories with explicit heads and three-way merges. Filesystem isolation and recovery checkpoints are the next priorities.

sorrel lane create
02

Slices

Experimental TS/JS context manifests. Inspect generated scope and unresolved imports before sharing repository content.

sorrel slice create
03

Runners

Local workflow execution with recorded results and redacted logs. Container execution remains experimental.

sorrel workflow run <job>
04

Vault

Resolve declared secret references under grants. This is not a credential scanner; audit existing history before uploading.

sorrel secret get <name>

The policy spine

Access stays explicit.

Hub verifies signed-in identity and consults configured Core grants. Signing in does not grant repository access, and editing project metadata does not create authority.

03 / WORKFLOW

Try the local workflow

Record a change.
Inspect the result.

04 / STATUS

Developer preview

Real foundation.
Deliberately early.

The published alpha provides a local VCS, Git bridge, sync, and review companion. Current source adds WorkOS browser login and hosted pilot setup. Live hosting validation, automatic integration, and recovery remain launch gates.

Working now

  • Persistent local object store and history
  • Lanes, stacks, and three-way merge
  • Git import, export, and colocated sync
  • SecretSpec injection and redacted run logs
  • Hub sync, proposals, and review flows

Still ahead

  • Production Hub authentication validation
  • Snapshot-bound checks and real integration
  • Checkpoints, undo, and separate lane directories
  • Stable embedding surface
  • Signed apps and remote Hub connections
